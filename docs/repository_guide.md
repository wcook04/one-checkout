# Repository guide

## One installable unit, one implementation

The runtime stays at `skills/one-checkout/scripts/one_checkout.py`. A copied
skill must work without the authoring repository. Moving the implementation
into a separate `src/` package would require a build/copy step or an external
installation; neither is needed for this standard-library script.

```text
skills/one-checkout/       installed instructions, licence and runtime
scripts/                  installer, demo shim, comparisons, stress and evaluation
tests/                    runtime, installer, layout and package contracts
docs/                     repository guide, provenance, release checks, policy
plugin.json               portable plugin identity; root skills/ discovery
.claude-plugin/            Claude-specific manifest; not a second skill copy
.github/                  CI and action dependency maintenance
```

This is a maintained source repository, not a registry of user installations.
There is no second implementation, generated API documentation, placeholder
`examples/` directory or private infrastructure dependency. `scripts/demo.py` forwards to the canonical installed demo; keep its command stable.
`scripts/recovery_demo.py` is a development-only fault comparison. It reuses the
bundled fixture and runtime; it is not an installed fault-injection interface.

## Canonical owners and copies

| Concern | Edit here | Relationship to other files |
|---|---|---|
| Git transaction and CLI | `skills/one-checkout/scripts/one_checkout.py` | Both installed copies receive these bytes. |
| Installed agent workflow | `skills/one-checkout/SKILL.md` | Resolve runtime/resources relative to this directory, never `../../docs/`. |
| Distribution membership | `skills/one-checkout/bundle.json` | Explicit allowlist; source inventory rejects accidental omissions or extras. |
| Licence | root `LICENSE` | `skills/one-checkout/LICENSE` is an intentional byte-identical distribution copy, checked in tests. |
| Plugin identity | root `plugin.json` | The Claude manifest adapts discovery; shared name/version/description/author/licence must agree. |
| Contributor guidance | `AGENTS.md`, `CONTRIBUTING.md` | These guide work on this repository; they are not installed runtime instructions. |
| Directory roles/interfaces | `docs/repository_layout.json` | `scripts/check_layout.py` validates selected Git paths, types and route text. |

The repository's `AGENTS.md` guides maintenance; `SKILL.md` is the installed
agent workflow. Host discovery is tested separately from file copying. Keep
installed guidance self-contained instead of linking to the authoring checkout.

## Adding a resource without breaking a copied skill

Place real agent-facing reference material under
`skills/one-checkout/references/`, scripts under its `scripts/`, and templates
under its `assets/` when those resources are needed. Declare each added file
in `bundle.json`. Refer to it from `SKILL.md` with a
skill-relative path. Keep development/release material in repository `docs/`;
it is not an installed resource.

The installer compares the source inventory against that allowlist before
writing either destination. Generated bytecode caches and `.DS_Store` files are ignored; symlinks and special files are
refused. The installer owns the precise cache policy. It does not automatically copy arbitrary new files. This inventory
check is not a secret scan or a proof that every instruction is correct.

Run the full tests, both installed-copy demos and the layout checks described
in `release_checks.md`. A resource addition also needs a test that actually
uses the resource from an installed copy. The existing declared-resource
fixture tests copying, not the semantics of every future resource.

## Layout checks protect interfaces, not aesthetics

`required_files` keeps public entry points and README-linked files present.
Those files, route carriers and role guides must be regular files.
`regular_files_only` extends that rule to all files in the installable skill.
The staged check obtains file modes from Git's index, not from a repaired
working tree. It does not follow worktree symlinks while reading a policy or
an interface. It is not a hostile-filesystem sandbox or a race-free snapshot.

`content_routes` checks declared text fragments, not general Markdown links,
anchors, external URLs or complete dependency closure. A new README file link
must name a `required_files` entry; the package tests enforce that convention.
Do not describe the layout check as a complete link checker or host validator.

Existing suffix rules apply only to their declared directory roles. Give a
new real role a purpose rather than imposing a universal scaffold. Tracked
files remain candidates even when an ignore rule matches them. An index check
reads staged policy and text, so an unstaged fix cannot approve a bad commit.

Local copies at `.agents/skills/one-checkout/` and
`.claude/skills/one-checkout/`, plus their tool-specific backup directories,
are ignored outputs here. Other agent configuration is not ignored. Installed
copies are not canonical sources: contribute changes to `skills/one-checkout/`
and reinstall, retaining any differing local copy with `--backup-existing`.
